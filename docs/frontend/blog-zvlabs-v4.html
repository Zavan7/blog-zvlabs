Celery e on_commit: por que a task não pode sair antes do commit

Uma corrida silenciosa entre o worker e o banco, e a linha de código que resolve.

Neste post

  • O problema
  • A correção

Quando a view cria um registro e já dispara uma task do Celery, o worker pode receber a mensagem antes de a transação ser confirmada. Na hora de buscar o registro, a task não o encontra. O erro aparece só de vez em quando, o pior tipo.

O problema

Repare no envio logo depois do create:

Se a requisição roda dentro de uma transação, o commit só acontece depois que a view termina. O worker, rápido, chega antes.

A correção

Adie o envio até o commit com transaction.on_commit. Se não houver transação aberta, a função roda na hora.

A task recebe apenas o id e busca o registro de novo quando roda. Assim ela sempre enxerga o estado já confirmado no banco.

Nos testes

Dentro de um TestCase, os callbacks de on_commit não rodam sozinhos. Use captureOnCommitCallbacks(execute=True) para vê-los executar.
